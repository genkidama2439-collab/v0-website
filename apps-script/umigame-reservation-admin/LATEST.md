# 最新のGAS変更

更新日: 2026-08-24

## 最新コード

現在の完全版：[`Code.gs`](Code.gs)

表示確認用：[`TestMail.gs`](TestMail.gs)

内容:

- **紹介パートナー制度（`2026.08.24-1`、本番未反映）**。予約一覧の末尾へ
  `紹介コード`・`紹介者名`・`紹介取得日時`・`紹介キャンペーン`を追加し、既存45列は移動しない
- `紹介者マスタ`・`紹介報酬ルール`・`紹介成果`を安全に作る`setupReferralProgram()`を追加。
  かいた君（`kaita`、売上の50%）は未登録の場合だけ追加する
- 報酬方式は売上率・予約固定・参加者単価に対応。プラン個別ルール→紹介者基本→0円の
  システム既定値の順に選び、紹介者側を円未満切り捨て、会社側を残額とする
- C1〜C6の分割行を再集計せず、Next.js確定済みの予約全体売上から予約番号1件につき
  紹介成果1行を作成。同じ予約番号の再送とマスタ変更では既存成果を上書きしない
- 紹介処理を既存`doPost`のレスポンスから分離し、マスタ・シート処理の例外で予約を失敗させない

- **メールアドレス列Vに残った旧チェックボックス入力規則の恒久対策（要再デプロイ）**。
  V列の規則違反で45列保存が失敗し、まるごと1日セットの海亀行だけが残った事故を受け、
  スキーマ更新時と新規予約の書き込み直前にV〜ASの不要な入力規則を除去する
- 保存後に予約番号・時間・プラン・金額を再読込し、要求した行数と内容が一致しなければ
  成功応答を返さない。再送時も既存行数が不足していれば`duplicate: true`にせずエラーにする
- **プランの振り分けを`planId`優先へ変更（反映済み）**。備考欄のテキストだけで
  昼夜セット・海空セット・まるごと1日セットを判定していたため、お客様が要望欄に
  「ドローンSUP」「ヤシガニ」「ナイト」「貸切」と書くだけで別プラン扱いになっていた。
  影響していた実例：
  - 昼夜セット(C1/C2)＋要望に「ドローンSUP」→ まるごと1日セット扱いになり、
    実在しないドローンSUPの行とカレンダー予定が作られる
  - 海空セット(C3/C4)＋要望に「ヤシガニ」「ナイト」→ まるごと1日セット扱いになり、
    ナイト開始時刻が取れず`doPost`が失敗し、**予約自体がエラーになる**
  - 通常セット＋要望に「貸切」→ 貸切単価で売上内訳が分割される
  `planId`が無い古い送信のときだけ従来のテキスト判定へ戻すため、過去データの再送は従来どおり動く
- A〜Uを予約管理・LINE安全送信用、V以降をメール、顧客行動ID、同意記録、流入・端末情報、参加者数値、要望用として45列へ統一
- 末尾へ`管理プランID`を追加し、新規予約の元プランを安定して識別
- 既存予約を削除せずに列見出しを追加する`ensureBookingSchema_`を追加
- T/Uがメール・Visitor IDになっている衝突構成だけを検出し、LINE列と顧客列を自動分離
- 修復完了後は予約受信のたびにシートの入力規則を書き直さず、読み込み・保存を軽量化
- U列へ残った`TRUE`/`FALSE`だけを初回修復時に除去
- B列の予約番号を基準に追記位置を決め、空行のT列に残った`FALSE`で1000行目へ飛ぶ問題を修正
- 同じ予約番号の再送は、シート追記・カレンダー・管理者メールを再実行せず成功応答だけ返す
- 空行T/Uの不要な値を初回修復時に除去し、実予約行のLINE確認・結果は保持
- 管理者メールの【お客様情報】へメールアドレスを追加
- 管理者メールへ`合計受取金額`を表示（単体プラン・全セット共通）
- セットの売上内訳の末尾へ`合計受取金額`を追加（内訳各行の実額を合算）
- Googleカレンダーのセット各イベントへ【セット全体の受取金額】ブロックを追加
- 現金の受取担当を「その日の最初のツアー」に固定し、他イベントは受け取らない旨を表示
- 金額の計算ロジックは変更なし。表示のみの変更

## 次回変更時の本番反映手順

1. サイトより先に、`Code.gs`を全選択コピーし、予約受付Apps Scriptの`Code.gs`へ貼り付けて保存（`setupSheet()`は実行しない）
2. `デプロイ` → `デプロイを管理` → 対象のウェブアプリを編集（鉛筆）
3. バージョンを`新バージョン`に変更して`デプロイ`（`/exec`のURLは変わらない）
4. このGASデプロイ完了後にサイト側をデプロイする
5. サイトからテスト予約を1件入れ、管理者メールとカレンダーの各予定を確認
6. 同じ画面での連打は行わず、確認後にテスト予約の予定を削除

今回の`planId`優先化を反映したあとは、次も合わせて確認してください。

- 昼夜セット(C1)で、要望欄に「ドローンSUP」と書いたテスト予約を1件送る
- シートに`昼夜セット海亀`と`昼夜セットヤシガニ`の2行だけができ、
  カレンダーも昼と夜の2件になること（ドローンSUPの行・予定が作られないこと）
- 海空セット(C3)で、要望欄に「ヤシガニ」と書いたテスト予約が
  エラーにならず、`海空セット（ウミガメシュノーケル）`と`海空セット（ドローンSUP）`の
  2行で保存されること

`doPost`はデプロイ済みバージョンのコードで動くため、手順3を省くと反映されません。
